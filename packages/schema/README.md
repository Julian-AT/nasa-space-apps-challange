# @terraluna/schema

Release bundle contracts for the web (PRD 8.4, 8.12, D23).

- `json/*.schema.json`: JSON Schema 2020-12, generated from the pydantic records in `pipeline/src/terraluna_pipeline/schema.py`.
- `src/generated/*.ts`: zod 4 schemas and inferred types, generated from that JSON Schema by `scripts/generate-zod.ts`. Do not edit them.
- `src/index.ts` exports `BundleManifestSchema`, `GateRecordSchema`, `ValidationSchema` (the array in `validation.json`), `ProductRecordSchema`, `SourcesSchema` (the array in `sources.json`), `WindowRecordSchema`, `FingerprintRecordSchema`, `WindowsSchema` (the array in `windows/{body}.json`), `ComparisonRecordSchema`, `ComparisonsSchema` (the array in `comparisons/{target_id}.json`), `TargetsSchema` (the array in `targets.json`) and `CardRecordSchema` (`cards/{card_id}.json`), each with its type of the same name without `Schema`.
- The science records keep cross-field rules as refinements, which do not narrow the inferred types. `distances_by_family`, and a card's `q5_stability.tied_by_family` and `tie_group_by_family`, are objects with exactly the four families; the other maps keyed by family (`by_family`, `rank_frequency`, `values_by_family`, `rank_by_family`) hold any subset of them. A tile layer's `legend` is a union told apart by `kind` (`classes` or `numeric`). Some rules compare values inside one document, so only pydantic checks them. Science records I: a Distribution's `values` are sorted and counted by `n`, a WindowPolygon's rings are closed, a WindowEntry's `terrain` and `radar` slots hold fingerprints of that kind, and an IncidenceRange's `min` does not exceed its `max`. Science records II: a card's `card_id` is `<target.target_window_id>__<earth.earth_window_id>`, its `comparison_ref` names the same two windows and the path `comparisons/<target.target_id>.json`, its q5 tie maps repeat each family's `tied` and `tie_group` from `distances_by_family`, a Mode B or C card has no available `radar_cpr` distance (PRD 4), and each figure letter appears at most once; a TileLayer's `zoom_min` does not exceed `zoom_max`, `metres_per_pixel_by_zoom` has one size per zoom from `zoom_min` to `zoom_max`, every omitted tile's z lies in that range, and `extent_m` is `[min_x, min_y, max_x, max_y]` with each min below its max; a numeric legend's `min` is below its `max`; a classes legend lists each code once; a WindowGrid's `n_eligible` does not exceed `n_generated`, and a Shortlist holds no more windows than `n_compared` (when those counts are set). Python writes every bundle file through those models.
- The science records also hold bounds that CONTRACTS a.4 does not spell out. Each follows from what the field means, and the JSON Schema and zod carry them, so a producer meets them when it writes a record: every number is finite (pydantic refuses NaN and infinities, which JSON cannot hold and zod refuses); fractions are 0 to 1 and `background_percentile` is 0 to 100; distances (`DistanceEntry.value` and the `ReferenceSpread` statistics) and nu values are at least 0, so a producer whose formula can round below zero, such as 1 − cosine similarity, handles that before writing; areas, grids, lags, supports and `coarsening_factor` are above 0; counts are 0 to 2^53 − 1, and `ReferenceSpread.n` and `RankFrequency.n` are at least 1 (a spread or frequency over nothing is null with its reason); `epsg` is at least 1; rings have at least 4 positions (RFC 7946 3.1.6); `acquisition_dates` are `YYYY-MM-DD`; `ExcludedObservable.reasons` is never empty (PRD 6.5); names, ids and map keys are non-empty strings. In science records II: `target_id` has the WindowId form (body-prefixed, lower case, for example `moon-cr-site01-w000`), so it is a safe file name in `comparisons/{target_id}.json`; `card_id` has the form `<window id>__<window id>`; a tile `layer` is one bundle path segment; `tile_px` is the integer 512, so pydantic refuses `512.0`; `window_m`, `stride_m`, pixel sizes and `support_m` are above 0; colour channels are 0 to 255 and a class code is a safe integer; `hillshade` azimuth is 0 to 360 and altitude 0 to 90 degrees; WebP `quality` is 0 to 100; a classes legend has at least one class; `projection.params` values are finite numbers or non-empty strings; zooms, tile indices and `bytes_total` are counts. A FigureRef has exactly one of `path` and `reason` (a figure not rendered says why), like the other value-or-reason pairs.
- The generated modules inline every `$defs` reference, so `windows.ts` is about 150 kB of source. Import only the schemas a route needs.

```ts
import { BundleManifestSchema } from '@terraluna/schema';

const manifest = BundleManifestSchema.parse(await response.json());
```

## Commands (from the repository root)

| Command | Does |
| --- | --- |
| `make schema` | Regenerates the JSON Schema, then the zod modules, in place |
| `make schema-check` | Fails, with a diff, if either generated output differs from the committed copy |
| `make check-ts` / `make test-ts` | ESLint and `tsc --noEmit`, and Vitest, through Turborepo |

The Vitest suite runs every case in `fixtures/schema-cases/cases.json`, the same cases the Python tests run, and parses `fixtures/mock-bundle/`. It also translates the synthetic schemas in `fixtures/schema-cases/generator-cases.json` and checks each document's verdict, and it evaluates each `if` condition the generator emits on that file's condition cases; the Python tests check the same verdicts against Draft 2020-12. `tests/types.test-d.ts` checks the inferred types and runs under `tsc`.

The tests read `pipeline/src/terraluna_pipeline/schema.py` and `fixtures/`, outside the package. Turborepo hashes both for the test task: the root `turbo.json` declares the fixtures, and `turbo.json` here adds `schema.py` with `$TURBO_EXTENDS$`, so a cached run never replays after either changes.

## Generator

`scripts/generate-zod.ts` inlines local `$defs` references, runs [json-schema-to-zod](https://github.com/StefanTerdell/json-schema-to-zod) (zod 4 output), and formats the result with prettier using explicit options. The converter turns any schema with `not` into `z.any()`, ignores `if`/`then` without `else` and an object's `allOf` of conditionals, and drops `propertyNames` from a map, so the script translates those keywords itself through the converter's `parserOverride` option. Both tools are pinned exactly in `package.json`, and each module header names their versions.

json-schema-to-zod 2.8.1 is the project's final release: active maintenance stopped in March 2026. The generated code is committed and checked for drift, so replacing the tool later changes only `src/generated/`.

The script refuses any JSON Schema it cannot translate with the same verdicts as pydantic and JSON Schema. A new keyword in `schema.py` therefore fails `make schema` instead of being dropped. It accepts:

- `type` `object` with `properties`, every property `required` and `additionalProperties: false`;
- a map: `type` `object` whose `additionalProperties` is a supported schema, with no `properties`, and optionally `propertyNames` of `{"minLength": 1}` or `{"enum": [<strings>]}`. It becomes `z.record(z.string(), V)`, `z.record(z.string().min(1), V)` or `z.partialRecord(z.enum([...]), V)`; the last accepts any subset of the keys and refuses others;
- `string` with `pattern`, `minLength` 0 or 1, `not`, `enum` or `const`; `integer` with safe-integer `minimum` and `maximum`, or with a safe-integer `const` and nothing but annotations beside it (pydantic's `Literal[512]`, which becomes `z.literal(512)`; a bound beside the `const` is refused, because the converter would drop it); `number` with finite `minimum`, `maximum` and `exclusiveMinimum`; `boolean`, optionally with a boolean `const`; `null`; `array` with `items` and optional non-negative safe-integer `minItems` and `maxItems`;
- `anyOf`, `title`, `description`, and `$schema` at the root;
- `not` holding only a `pattern`, with or without `type: string`: a string in which the pattern finds no match;
- pydantic's discriminated union (`Annotated[A | B, Field(discriminator="kind")]`), alone or as the non-null branch of a nullable `anyOf`: an untyped schema holding exactly `oneOf`, `discriminator` and optional annotations. The `oneOf` is a non-empty array of `$ref`s, each to a record object whose discriminator property is required and is exactly `{"type": "string", "const": "<non-empty value>"}`, with no two branches sharing a value. `discriminator` is exactly `propertyName` and `mapping`, and `mapping` has one entry per branch value, each `#/$defs/<Name>` of the definition that branch references (checked before the references are inlined). JSON Schema 2020-12 treats `discriminator` as an annotation, so the verdict is plain `oneOf`; the converter emits `z.discriminatedUnion("kind", [...])`, which gives the same verdict because each branch fixes `kind` to a different string. Any other `oneOf`, a `discriminator` without a `oneOf`, or a `oneOf` beside `type`, `anyOf` or `not` is refused, because the converter would translate a plain `oneOf` as `z.any().superRefine`;
- on a record object, a conditional at the top level and/or a non-empty `allOf` of conditionals. A conditional is `if` and `then`, with an optional `else`: `if` holds only `properties`, each exactly `{"const": <string>}`, `{"const": <safe integer>}` or `{"type": "null"}`, and `required` naming those properties; `then` and `else` hold only a non-empty `properties`, each a supported schema. All of them name properties of the same object. The zod schema refines the object once for each conditional: when every `if` property is present and passes its test, each `then` property must match its schema, and otherwise each `else` property. A failing property gives one issue for each issue of its schema, at the path below the property, with the message `Invalid input: must match the "then" schema when the "if" schema holds: ` (or `... the "else" schema when the "if" schema fails: `) followed by the nested message. ProductRecord uses a top-level conditional for `verification_status: VERIFIED` (PRD 8.12); the science records put theirs in `allOf`, for example DistanceEntry's "status available ⇔ value set ⇔ reason null".

Patterns must be printable ASCII without `.`, class escapes such as `\d`, negated or empty classes, or `(?` groups. These constructs match differently in pydantic's Rust regex engine and in a JavaScript `RegExp`.

JavaScript cannot tell `1.0` from `1`, and it rounds integers above 2^53. zod therefore accepts `1.0` where pydantic's strict mode refuses it. The shared cases avoid such numbers, and `validate_bundle` in Python remains the authoritative bundle check.
