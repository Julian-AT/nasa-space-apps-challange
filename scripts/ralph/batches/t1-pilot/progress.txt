- ralph.sh matches story `files` with bash `[[ $p == $glob ]]`, so `*` also matches `/`: `pipeline/*` covers nested paths.
- Context7 works over plain HTTP via WebFetch: https://context7.com/api/v1/<org>/<repo>?topic=<words>&tokens=<n>. For flags of an installed CLI, `<cli> --help` is authoritative.

- Bundle records live in pipeline/src/terraluna_pipeline/schema.py. Base `Record` uses extra=forbid, strict=True, frozen=True and regex_engine="rust-regex". Constraints are kept to what JSON Schema can express (patterns, enums, minLength, minimum), so T0-03/T0-04 can stay in parity.
- Parity traps for T0-03 (both checked with jsonschema 4.26.0): (1) the Python `jsonschema` package matches `pattern` with `re.search`, where `$` also matches before a trailing newline, so "<64 hex>\n" passes `^[0-9a-f]{64}$` there but fails pydantic (rust-regex) and ECMA/zod. (2) pydantic strict rejects JSON `1.0` for an int, while JSON Schema `integer` accepts it and JS cannot tell 1.0 from 1.
- mypy --strict reports a tuple of lambdas that are called later as no-untyped-call. Call the functions directly.
- `mktemp` + `mv` leaves a file with mode 600. Run `chmod 644` after a jq rewrite of prd.json. `jq .` reproduces prd.json's formatting byte for byte.
- The Codex reviewer runs in a read-only sandbox, so it marks every check command NOT_RUN. Only the Claude reviewer and the gate run commands. To show that a resolution edit changed only resolution fields, compare the hash of `jq 'del(.findings[].resolution)'` before and after.
- Bundle I/O lives in pipeline/src/terraluna_pipeline/export.py: write_bundle, validate_bundle (returns BundleError(code, path, message); codes are the ErrorCode Literal), budget_errors over BUDGETS (PRD 8.4 table order), canonical_json and the mock bundle. CLI: `uv run python -m terraluna_pipeline.export validate <dir> [--production] | mock-bundle <dir> | mock-bundle-check <dir>`. `make mock-bundle` and `make mock-bundle-check` wrap the last two.
- Claude Code's safety check blocks shell commands with `rm -rf` on a variable (also inside heredocs or Makefile recipes) and the agent must not work around it. Design targets so nothing deletes a directory: overwrite in place, and use Python `tempfile.TemporaryDirectory` for scratch space.
- commitlint: a body line that starts with `word:` is parsed as a footer token and gives a footer-leading-blank warning. Do not start body lines with "x:".
- Python stdlib traps: `json.loads` accepts NaN/Infinity unless `parse_constant` refuses them, and raises RecursionError (not ValueError) on deep nesting. `Path.walk()` (3.12) puts symlinks to directories in filenames, unlike `os.walk`.
- JSON Schema generation lives in schema.py: CONTRACTS (name as used in fixtures/schema-cases, file name, TypeAdapter), generate_json_schemas, write_json_schemas and json_schema_differences. CLI: `uv run python -m terraluna_pipeline.schema write <dir> | check <dir>`; `make schema` and `make schema-check` wrap them for packages/schema/json. pydantic's GenerateJsonSchema already orders keywords and keeps properties in field order, so the output is deterministic without sort_keys. T0-04 extends both make targets with zod.
- How T0-03 handled the parity traps: (1) the Python tests evaluate JSON Schema `pattern` as ECMA-262 (trailing `$` becomes `\Z`) via jsonschema's validators.extend, and the translator raises on constructs that differ between the engines (\d, \w, \s, `.`, `(?`, negated or empty classes); (2) cases.json uses no integral floats and no integer beyond ±2^53, and BundleFile.bytes is capped at JS_MAX_SAFE_INTEGER. jsonschema 4.26 (draft 6 and later) treats 1.0 as an integer, as JS does; only pydantic strict rejects it.
- types-jsonschema 4.26 leaves `validators.extend` untyped, so mypy --strict needs `# type: ignore[no-untyped-call]` on that call. It types `is_valid` input as a JSON value, so pass `Any`, not `object`.
- rasterio 1.5.2 has no py.typed, and the root pyproject.toml is outside most story file lists, so every rasterio import carries `# type: ignore[import-untyped]` (affine 3.0.1 and numpy are typed). Untyped results are Any: annotate them (`transform: Affine = src.window_transform(w)`).
- rasterio traps (checked with 1.5.2 / GDAL 3.12.2): `src.read(window=...)` silently clips a window that leaves the raster and accepts fractional windows; a file without a geotransform reads as the identity transform with a NotGeoreferencedWarning. io.read_geotiff_window refuses such windows and reports transform None. A CRS written to a GeoTIFF reads back as a different WKT than `CRS.from_string(...).to_wkt()`, so test against the WKT read back from the file.
- ProductRecord conventions (schema.py): a field that applies but was not established is "unknown"; null means does not apply, and is how source_url, local_path and checksum say "none". local_path must match `^data/(raw|interim|processed)/...` (relative, so no home directory leaks). A VERIFIED record needs local_path, checksum and units other than "unknown" in any case (model validator plus JSON Schema if/then). Rebuild a record with `ProductRecord.model_validate({**r.model_dump(), ...})`, never `model_copy(update=...)`, which skips validation.
- schema.has_url_credentials / CREDENTIAL_URL_PATTERN reject userinfo and signed or token query/fragment parameters (SIGNED_URL_TOKENS, any case, substring match). The JSON Schema states forbidden patterns as `not: {pattern}`; test_json_schema's oracle test requires `^...$` only for patterns not under `not`.
- io.py API: sha256_file(path, chunk_size=); read_geotiff_window(path, window=None, band=1) -> RasterWindow; read_product(product_id, [one_file], ProductMetadata, root=repo_root, window=None) -> (bands, ProductRecord PARTIAL); fetch_range(url, first, last, timeout=) -> RangeResponse (inclusive range; raises RangeNotSupportedError on 200 without reading the body, RangeReadError otherwise; ValueError for signed or non-http URLs before any request).

- Declaring an already-installed transitive package as a direct dependency: `uv lock --offline` works and only adds requirement lines to uv.lock.
- URL guard, amended in T1-01 round 1: CREDENTIAL_URL_PATTERN also refuses a percent-encoded RFC 3986 unreserved character (`_ENCODED_UNRESERVED`: letters, digits, -._~, either hex case) after `?` or `#`, and the `=` of a token also matches `%3D`. Reserved encodings (%2F, %20) and any encoding in the path stay allowed. Keep it one regex in the ECMA/Python/Rust subset; use plain `(...)` groups, because the test oracle refuses `(?`.
- read_product's `root` is optional and defaults to `Path.cwd()`, because commands run from the repository root. A file outside root/data/{raw,interim,processed} is refused with 'run from it or pass root'. Test the default with `monkeypatch.chdir(tmp_path)`.
- quality.py API (T1-02): validity_mask(values, *, nodata=None, support=None) -> ValidityMask(valid bool, reason uint8; both read-only copies; reason_counts() -> {InvalidReason: int} in enum order). Codes VALID 0, NODATA 1, NON_FINITE 2, OUTSIDE_SUPPORT 3, ISIS_SATURATION 4; precedence nodata > isis_saturation > non_finite > outside_support. valid_fraction(ValidityMask | bool ndarray) -> ValidFraction(valid_pixels, total_pixels; .fraction, .invalid_pixels); it raises ValueError on an empty window and TypeError on a non-bool array. Pass rasterio's RasterWindow.nodata as nodata; declared nodata is compared in the array dtype.
- ISIS special pixels: the header is isis/src/core/include/SpecialPixel.h on branch dev of DOI-USGS/ISIS3 (the old objs/SpecialPixel path returns 404). 4-byte real Null 0xFF7FFFFB, Lrs..Hrs 0xFF7FFFFC..0xFF7FFFFF (Hrs = -FLT_MAX, which GDAL products also use as nodata), smallest valid 0xFF7FFFFA. Integer ISIS nulls (0 for unsigned) are not matched automatically.
- numpy 2.5: `np.errstate(over="ignore")` silences the float64 -> float32 cast overflow warning. Comparing a 0-d array gives a numpy scalar, not an ndarray; wrap with np.asarray. `astype(..., casting="same_value")` (new in 2.4) raises when a cast changes a value.
- quality.py nodata contract (T1-02 round 1): declared nodata keeps its exact value (Fraction, or NaN/inf) until it meets the dtype. Integer arrays compare the exact integer. Floating and complex arrays accept only a value that is exactly a binary64 double, rounded once to the dtype; others raise ValueError. long double and clongdouble arrays raise TypeError on every platform. numpy itself double-rounds a large Python int to float32 (np.float32(2**60 + 2**36 + 1) == 2**60), and numpy integer scalars have no as_integer_ratio. On this arm64 Mac np.longdouble is binary64 (np.dtype equality with float64 is True, but dtype.type is np.longdouble still tells them apart).
- pilot.py API (T1-03): `uv run python -m terraluna_pipeline.pilot {fetch|record|check} <source>`. A source implements the Source protocol (a `name` property, `fetch(raw_dir, download, now)`, `build(raw_dir, root) -> Build(files, records, record_prefix)`) and is registered in `pilot.SOURCES`. fetch stages downloads in `data/raw/<source>/.fetch-*` (TemporaryDirectory), moves them into place only after every download succeeded and writes `fetch.json` last; record and check refuse raw files whose size or sha256 differs from fetch.json. The sources.json upsert replaces every record under the source's product_id prefix (pgda78: `PGDA78/Site01/`) and keeps the others; outputs go through export.canonical_json. Tests inject `sources=`, `download=` (a mock with io.fetch_file's signature) and `now=`.
- io.fetch_file(url, dest, *, max_bytes=WHOLE_FILE_LIMIT_BYTES (200_000_000), magic=(), timeout=60) -> FetchedFile downloads one whole file below the limit (FileTooLargeError before reading the body otherwise; DownloadError for anything else, naming the URL). `magic` guards against soft 404s.

The README defines the suffixes and units; only the products/78 page links Site01_ROIs.tgz. Downloads run at about 0.7 MB/s, so a full Site01 fetch (5 x 41 MB) takes about 5 minutes.

- Engineering choices: (1) The DEM's ProductRecord is VERIFIED (downloaded, decoded, masked and plotted, the PRD 5 entry rule). The other GeoTIFFs are PARTIAL because they are not plotted, and the ROI archive is PARTIAL. (2) Files at or over 200 MB make fetch fail with FileTooLargeError instead of downloading. Every Site01 file is about 41 MB, so pgda78 needs no windowed read; a source that does (T1-04) uses fetch_range. (3) The upsert replaces every record under PGDA78/Site01/, so a product the source stops producing is removed; other sources' records are kept. (4) Units come from README phrases ('(meters)', 'in degrees', ...). A missing phrase gives "unknown" and PARTIAL. (5) version, acquisition_time and effective_resolution are "unknown"; the radar fields are null; the reasons are in field_notes. G0 and the shipping mode are not written.
