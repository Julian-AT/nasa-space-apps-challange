## Codebase Patterns
- Build Mac, checked 2026-11-14: uv 0.9.26; Python 3.12.13 via uv; Node 22.23.3 (nvm); pnpm 12.16.1; jq 1.8.2; GNU Make 3.81; actionlint installed.
- `python3` on PATH is Anaconda's 3.14. Always use `uv run`, never bare `python3`.
- GNU Make 3.81: no .ONESHELL, no grouped targets (`&:`), no `!=` assignment. Keep recipes POSIX sh.
- No system GDAL (`gdalinfo` is missing). GDAL comes from the rasterio wheel.
- macOS has no coreutils `timeout`.
- Other workers may share this repository. Stage explicit paths only.
- Commits: commitlint (config-conventional, scopes lower case such as t0-01) runs from the husky commit-msg hook (core.hooksPath=.husky/_). The root package.json already exists for this; T0-04 extends it.
- ralph.sh commits review files, gate results, loop notes and compact logs (logs/agents/<date>/*.jsonl). Full transcripts are in git-ignored logs/agents/<date>/raw/.
- ralph.sh matches story `files` with bash `[[ $p == $glob ]]`, so `*` also matches `/`: `pipeline/*` covers nested paths.
- Context7 works over plain HTTP via WebFetch: https://context7.com/api/v1/<org>/<repo>?topic=<words>&tokens=<n>. For flags of an installed CLI, `<cli> --help` is authoritative.
- The uv workspace root is virtual (no [project]). A plain `uv sync --locked` there installs both members and the dev group (checked on a fresh copy).
- Bundle records live in pipeline/src/terraluna_pipeline/schema.py. Base `Record` uses extra=forbid, strict=True, frozen=True and regex_engine="rust-regex". Constraints are kept to what JSON Schema can express (patterns, enums, minLength, minimum), so T0-03/T0-04 can stay in parity.
- Parity traps for T0-03 (both checked with jsonschema 4.26.0): (1) the Python `jsonschema` package matches `pattern` with `re.search`, where `$` also matches before a trailing newline, so "<64 hex>\n" passes `^[0-9a-f]{64}$` there but fails pydantic (rust-regex) and ECMA/zod. (2) pydantic strict rejects JSON `1.0` for an int, while JSON Schema `integer` accepts it and JS cannot tell 1.0 from 1.
- mypy --strict reports a tuple of lambdas that are called later as no-untyped-call. Call the functions directly.
- `mktemp` + `mv` leaves a file with mode 600. Run `chmod 644` after a jq rewrite of prd.json. `jq .` reproduces prd.json's formatting byte for byte.
- The Codex reviewer runs in a read-only sandbox, so it marks every check command NOT_RUN. Only the Claude reviewer and the gate run commands. To show that a resolution edit changed only resolution fields, compare the hash of `jq 'del(.findings[].resolution)'` before and after.
- Bundle I/O lives in pipeline/src/terraluna_pipeline/export.py: write_bundle, validate_bundle (returns BundleError(code, path, message); codes are the ErrorCode Literal), budget_errors over BUDGETS (PRD 8.4 table order), canonical_json and the mock bundle. CLI: `uv run python -m terraluna_pipeline.export validate <dir> [--production] | mock-bundle <dir> | mock-bundle-check <dir>`. `make mock-bundle` and `make mock-bundle-check` wrap the last two.
- Claude Code's safety check blocks shell commands with `rm -rf` on a variable (also inside heredocs or Makefile recipes) and the agent must not work around it. Design targets so nothing deletes a directory: overwrite in place, and use Python `tempfile.TemporaryDirectory` for scratch space.
- commitlint: a body line that starts with `word:` is parsed as a footer token and gives a footer-leading-blank warning. Do not start body lines with "x:".
- Python stdlib traps: `json.loads` accepts NaN/Infinity unless `parse_constant` refuses them, and raises RecursionError (not ValueError) on deep nesting. `Path.walk()` (3.12) puts symlinks to directories in filenames, unlike `os.walk`.
- JSON Schema generation lives in schema.py: CONTRACTS (name as used in fixtures/schema-cases, file name, TypeAdapter), generate_json_schemas, write_json_schemas and json_schema_differences. CLI: `uv run python -m terraluna_pipeline.schema write <dir> | check <dir>`; `make schema` and `make schema-check` wrap them for packages/schema/json. pydantic's GenerateJsonSchema already orders keywords and keeps properties in field order, so the output is deterministic without sort_keys. T0-04 extends both make targets with zod.
- How T0-03 handled the parity traps: (1) the Python tests evaluate JSON Schema `pattern` as ECMA-262 (trailing `$` becomes `\Z`) via jsonschema's validators.extend, and the translator raises on constructs that differ between the engines (\d, \w, \s, `.`, `(?`, negated or empty classes); (2) cases.json uses no integral floats and no integer beyond ±2^53, and BundleFile.bytes is capped at JS_MAX_SAFE_INTEGER. jsonschema 4.26 (draft 6 and later) treats 1.0 as an integer, as JS does; only pydantic strict rejects it.
- types-jsonschema 4.26 leaves `validators.extend` untyped, so mypy --strict needs `# type: ignore[no-untyped-call]` on that call. It types `is_valid` input as a JSON value, so pass `Any`, not `object`.

- generate-zod.ts translates two keywords itself through json-schema-to-zod's `parserOverride` (translateOverride), because 2.8.1 turns any `not` into z.any().refine(...) (dropping type and pattern) and ignores `if`/`then` without `else` on an object: `not` holding only a portable `pattern` (typed string or untyped) becomes `z.string()...refine(text => !new RegExp(P).test(text))`, and an object's `if` (properties of exactly `{const: <string>}` plus matching `required`) / `then` (only `properties`, each a supported schema, all naming the object's own properties) becomes a superRefine with Draft 2020-12 semantics. assertSupported admits only those forms; `else`, `oneOf` and the rest still throw. Inside the override, call `parseSchema(rest, refs, true)` (blockMeta) and append `.describe()` yourself, since an override's string skips the converter's describes.
- `zodExpression(schema)` (generate-zod.ts) returns the same plain-JavaScript zod expression a module gets; the generator tests evaluate it with `new Function('z', ...)` (one eslint-disable for no-implied-eval). fixtures/schema-cases/generator-cases.json holds synthetic schemas with authored verdicts: Python checks them with the Draft 2020-12 ECMA oracle, Vitest checks the generated zod. Use it for any new keyword the generator learns.
- A generated module must never contain `z.any(` (a test enforces it): that is the converter's fallback for a schema it does not understand.
- generate-zod.test.ts parses schema.py's `CONTRACTS: tuple[Contract, ...] = (` block with a regex and requires the zod CONTRACTS to equal it in names, file names and order. Keep each entry as `Contract("<Name>", "<file>.schema.json", ...)` on its own line.
- To compare zod with pydantic beyond the shared cases, a scratch Node script can `await import(pathToFileURL('<repo>/packages/schema/src/index.ts').href)` from anywhere: zod resolves from the package, and Node 22.23 strips the types.
- A package can widen its own turbo task inputs without touching the root turbo.json: `<pkg>/turbo.json` with `"extends": ["//"]` and `"inputs": ["$TURBO_EXTENDS$", "$TURBO_ROOT$/<path>"]` (`$TURBO_EXTENDS$` first; Turborepo ≥ 2.7). packages/schema/turbo.json does this for schema.py. `--dry=json` `.resolvedTaskDefinition.inputs` omits `$TURBO_DEFAULT$`; count the package files in `.tasks[].inputs` to confirm the defaults survived.
- Every generator object requires all of its properties, and zod 4 skips refinements after a missing-key issue, so a full-document case cannot observe how the if/then refinement treats an absent property. The `conditionCases` in generator-cases.json test `conditionSource` (exported from generate-zod.ts) directly. A temporary mutation of the generator followed by a test run is a quick way to show that a test is not vacuous. Restore the file from a copy, and never edit files outside the story's files for this.
- A Vitest file that reads a missing file, or calls a missing export, at collection time fails as "no tests". When writing failing tests first, do those reads inside each `it`, so only the new tests fail and the run shows a count.
- pydantic 2.14 strict traps for science records: `Literal[False]` matches by equality, so 0 and 0.0 pass (Strict() on a Literal raises RuntimeError), so schema.py uses NotIndependent with a BeforeValidator that refuses non-bools; a float accepts JSON `NaN` unless `allow_inf_nan=False`, hence the Float/Fraction/Positive/NonNegative types; `tuple[...]` refuses a Python list in strict mode, so fixed-length pairs are `list[Float]` with min/max length. Strict floats accept JSON integers, as JSON Schema `number` and `z.number()` do.
- Cross-field rules in schema.py are a pydantic model_validator plus `_when(condition, then, otherwise)` conditionals in `json_schema_extra={"allOf": [...]}`. generate-zod.ts translates `if` tests `{"const": <string or safe integer>}` and `{"type": "null"}`, `then`/`else` of `properties` only, at the top level or in an object's allOf, as one superRefine each. Rules that compare values inside one document (sorted values, n == len(values), closed rings, WindowEntry slot kinds) stay pydantic-only; test_json_schema.py proves JSON Schema accepts them and that every other combination agrees.
- generate-zod.ts also translates `number` (minimum, maximum, exclusiveMinimum), boolean `const`, array minItems/maxItems and maps (`additionalProperties` schema, optional `propertyNames` {minLength: 1} or {enum}) as z.record / z.partialRecord; json-schema-to-zod 2.8.1 has no prefixItems and silently drops propertyNames. Generated modules inline every $defs reference: windows.ts is about 150 kB of source.
- provenance.py (T0B-01) holds run_id, config_version, file_hashes, command_line and a copy of canonical_json; export.py keeps its own until a later story imports provenance's (CONTRACTS c.4). A three-way verdict fuzz works from a /tmp script that puts pipeline/tests on sys.path, imports test_json_schema's pydantic_accepts and EcmaValidator, writes documents with both verdicts, and a Node script that imports packages/schema/src/index.ts compares zod.

No shared case can test it. packages/schema/README.md also lists every single-field bound beyond CONTRACTS a.4; extend that list with each new bound.

The loop's resolve checks are in ralph.sh: digest of `jq -S 'del(.findings[].resolution)'` unchanged, every resolution fixed or rebutted, every fix commit an ancestor of HEAD.
- A pipeline such as `cmd | tail -3` reports tail's exit status, so `&& git commit` after it commits even when cmd failed (T0B-02 committed one mypy error this way, fixed in the next commit). Run a check without a pipe and print `$?`, or redirect to a log and grep it.

Since 3e790c9, test_schema_science.py finds the T0B-01 block by `files.index(T0B_01_CONTRACTS[0])` and compares the contiguous slice, and test_schema_cards.py pins its two by index from a known predecessor (`files.index(("Comparisons", ...)) + 1`). T0B-02 to T0B-04 list test_schema_science.py in their files for this (orchestrator, 2026-11-15).
- generate-zod.ts (T0B-02) accepts pydantic's discriminated union (`Annotated[A | B, Field(discriminator="kind")]` becomes an OpenAPI `discriminator` next to a `oneOf` of `$ref`s, nullable as `anyOf` [union, null]) and an integer `const` (`Literal[512]`). dereference inlines `oneOf` and checks the mapping against the `$ref` names before they are lost; json-schema-to-zod's own simpleDiscriminatedOneOf path then emits `z.discriminatedUnion`, with every branch check intact. Other `oneOf` forms are still refused. pydantic matches `Literal[512]` by equality (512.0 passes), so TilePx adds a BeforeValidator that refuses non-ints.
