- No system GDAL (`gdalinfo` is missing). GDAL comes from the rasterio wheel.
- macOS has no coreutils `timeout`.
- Other workers may share this repository. Stage explicit paths only.
- Commits: commitlint (config-conventional, scopes lower case such as t0-01) runs from the husky commit-msg hook (core.hooksPath=.husky/_). The root package.json already exists for this; T0-04 extends it.
- ralph.sh commits review files, gate results, loop notes and compact logs (logs/agents/<date>/*.jsonl). Full transcripts are in git-ignored logs/agents/<date>/raw/.
- ralph.sh matches story `files` with bash `[[ $p == $glob ]]`, so `*` also matches `/`: `pipeline/*` covers nested paths.
- Context7 works over plain HTTP via WebFetch: https://context7.com/api/v1/<org>/<repo>?topic=<words>&tokens=<n>. For flags of an installed CLI, `<cli> --help` is authoritative.
- The uv workspace root is virtual (no [project]). A plain `uv sync --locked` there installs both members and the dev group (checked on a fresh copy).
- Bundle records live in pipeline/src/terraluna_pipeline/schema.py. Base `Record` uses extra=forbid, strict=True, frozen=True and regex_engine="rust-regex". Constraints are kept to what JSON Schema can express (patterns, enums, minLength, minimum), so T0-03/T0-04 can stay in parity.
- Parity traps for T0-03 (both checked with jsonschema 4.26.0): (1) the Python `jsonschema` package matches `pattern` with `re.search`, where `$` also matches before a trailing newline, so "<64 hex>\n" passes `^[0-9a-f]{64}$` there but fails pydantic (rust-regex) and ECMA/zod. (2) pydantic strict rejects JSON `1.0` for an int, while JSON Schema `integer` accepts it and JS cannot tell 1.0 from 1.
- mypy --strict reports a tuple of lambdas that are called later as no-untyped-call. Call the functions directly.
- `mktemp` + `mv` leaves a file with mode 600. Run `chmod 644` after a jq rewrite of prd.json. `jq .` reproduces prd.json's formatting byte for byte.
- Polarimetry results are `StatedArray(value, state, reason)` from terraluna_pipeline.polarimetry: float64 NaN exactly where state != VALID, and reason NONE exactly where VALID. Construction validates and freezes it. Build new rules with the private `_Classifier` (first matching rule wins), and add new codes to `InvalidReason` (value == name, at most 32 chars).
- Name fixture tests `test_F<n>_...` so T2-06 can list the required G1 test ids.
- Masks never enter polarimetry.py implicitly: every array argument goes through `_real_array` or `_bool_mask`, which refuse numpy masked arrays (TypeError). New array arguments must use these helpers, and product flags are explicit arguments (nodata, noise or validity flags).
- polarimetry.py array inputs pass `_require_plain` (an allowlist walked iteratively to every depth): exact np.ndarray or np.memmap, scalars (bool, int, float, complex, str, bytes, np.generic), and lists and tuples up to 64 levels. Anything else raises TypeError (masked arrays at any depth, np.ma.masked, custom sequences, `__array__` objects such as xarray or pandas, third-party ndarray subclasses such as unit-carrying ones), so callers convert explicitly and pass masks as flags. Object-dtype ndarrays pass the walk and are refused by each caller's dtype check; keep that check in any new entry point.
- Update to the bullet above (T2-01 round 3, 0f41cd7): every type in `_require_plain` is matched exactly, never by isinstance. Lists and tuples are `type(x) is list/tuple`, Python scalars are exact bool/int/float/complex/str/bytes plus this module's ObsState and InvalidReason, and numpy scalars count only when `np.dtype(type(x)).type is type(x)`. Subclasses of any of these raise TypeError, since a list subclass with `__array__` hands numpy a masked array the walk never saw. mypy narrows on `type(x) is list`, not on `type(x) in (...)`.
- Results float64 cannot hold are per-element states, never whole-array errors: call `_Classifier.mark_out_of_range(result, positive=...)` after computing a result, which marks INVALID/FLOAT64_OUT_OF_RANGE where the result is non-finite (overflow) or, for a positive quantity, below the smallest normal float64. Compute so intermediates cannot overflow first (decoding uses `(DN * 10**(-offset/20))**2`). This is representability, not a physical threshold.
- Tolerances are `Tolerance(rtol, atol)` from polarimetry.py (finite, not negative, stored as float); `ARITHMETIC_TOLERANCE` is the PRD 7 rtol 1e-10 / atol 1e-12. Use it as the default for later validity tolerances (T2-03 PSD check) and say that the real-data value is open.
- Several outputs from one input share rules through `_Classifier.copy()`: classify the shared input rules once, then copy per output. For a quantity that may be a valid exact zero (SC, CPR), use `mark_below_normal(result, nonzero=<exact test on the inputs>)` instead of `mark_out_of_range(positive=True)`, and decide signs and zeros from the inputs (`s1 <= -s4`, `s1 != s4`), not from the rounded result.
- Stokes results are `CircularPowers(total, sc, oc, cpr, convention, tolerance)` from `circular_from_stokes(s1, s4, *, s2, s3, convention, product_masked, tolerance)`; s2/s3 and product_masked have no default. T2-04's derive_circular should wrap it, not reimplement it.
- A tolerance stated on an inequality applies to that inequality as written. Do not move it onto an equivalent form (a square root, a ratio): on the norm, the relative part of a tolerance on squares is about twice as loose. For a squared bound that must not overflow, scale each pixel by one exact power of two (`np.frexp` of the largest magnitude, then `np.ldexp(x, -e)` and `np.ldexp(atol, -2 * e)`). `_beyond_squared_bound` in polarimetry.py does this, and T2-03's PSD check can follow the same pattern. Test such rules against an exact `fractions.Fraction` oracle over the whole finite float64 range, skipping a declared rounding band.
- Test-only helpers live in pipeline/tests/polarimetry/ (a package with __init__.py). pytest puts pipeline/tests on sys.path, so they import as `polarimetry.<module>`; mypy (explicit package bases from the repo root) names them `pipeline.tests.polarimetry.<module>`. Import them with `if TYPE_CHECKING: from pipeline.tests.polarimetry import x` / `else: from polarimetry import x`. The root pyproject (not owned by this batch) would be the clean fix, via pytest `pythonpath` and mypy `mypy_path`.
- `np.outer(k, k.conj())` is not exactly Hermitian here: with fused multiply-add, `k_i * conj(k_i)` keeps an imaginary part near 1e-17. Build exact fixtures from the upper triangle, its conjugate and a real diagonal (`jones_oracle.covariance_of`).
- `np.linalg.eigvalsh` on a stack holding a NaN matrix returns garbage for that matrix without raising, and it overflows to inf for elements near 1e308. Zero non-finite matrices after classifying them, and scale each matrix by a power of two first (`_scale_by_power_of_two` in polarimetry.py).
- Covariance results are `CovarianceCircularPowers(total, sc, oc, cpr, base_sc, handedness_term, handedness_ratio, convention, ordering, tolerance, handedness_verified=False)` from `circular_from_covariance(covariance, *, ordering, convention, product_masked, tolerance)`, with covariance of shape (..., 3, 3). T2-04's derive_circular should wrap it. T2-05 can reuse `CIRCULAR_BASIS`, `_scale_by_power_of_two`, `_unscaled_power` and `_ratio`.
- Update to the covariance bullets above (T2-03 round 1): (1) A diagnostic that is a difference of two quadratic forms must be one linear functional, `Re sum(C' * K)` with `K = (M_a - M_b)/2` and `M = np.outer(u, u.conj())` built from basis rows (`_HANDEDNESS_FORM`). The difference of two rounded powers loses a term far below the powers. (2) The per-matrix power-of-two scaling must not drop parts. circular_from_covariance refuses (INVALID/FLOAT64_OUT_OF_RANGE, rule 3) a matrix with a nonzero part below 2**-1016 times its largest part (`_CARRIED_RANGE`, from the factors of at least 1/16 on the way into a result). T2-05 reusing `_scale_by_power_of_two` needs the same guard, with the headroom recomputed for its own factors. (3) For range properties, the scatterers (2**i, 0, 2**i) and (0, 2**j, 0) give A = B = C = 2**(2i) and V = 2**(2j). The large parts cancel exactly (SC = V, OC = A), so the exact results are known at any magnitude.
- derive_circular(input_kind, data, convention, validity_mask, *, tolerance) wraps the two conversions: STOKES_INPUT with StokesInput(s1, s4, s2, s3) returns CircularPowers; COVARIANCE_INPUT with CovarianceInput(covariance, ordering) returns CovarianceCircularPowers (typed by overloads). validity_mask is bool, True = valid (the opposite polarity of product_masked). T2-05/T2-06 should call it, not the lower functions, where an interface test is wanted.
- aggregate_blocks(circular, *, block_size) takes only CircularPowers or CovarianceCircularPowers on a 2-D grid that divides into whole blocks, and returns BlockAggregates: mean_sc, mean_oc, ratio_of_mean_powers (primary, PRIMARY_RADAR_STATISTIC) and mean_of_pixelwise_ratios as StatedArrays over the block grid, power_support and ratio_support (BlockSupport: n_pixels, n_valid, n_missing, n_invalid_by_reason as a read-only mapping, valid_fraction), block_origin (grid, 2) int64 and blocks_independent False. Block sums run at one power-of-two scale per quantity per block (`_scaled_sums`), and the ratio divides frexp mantissas so the division cannot overflow. Reuse these for any later block statistic (e.g. the handedness ratio per window).
- Update to the aggregate_blocks bullet above (T2-04 round 1, 5d57ddc): block sums are exact Python ints counting 2**-1074 (`_exact_sums`); `_scaled_sums` and the frexp-mantissa ratio are gone. Signs and zeros come from the exact sums (`_signs`), and each statistic is rounded once by int true division (`_rounded_quotients`: correctly rounded, subnormals included; OverflowError becomes an infinity for the range rule). Any statistic that tests the sign or zero of a sum of signed values (powers negative within the tolerance) needs an exact sum: a float64 sum keeps or loses a cancelling residual depending on the pixel order. Cost: about 0.2 s per million values per quantity.
- dB exists only as DecibelArray from to_db_for_display (display only). Records holding powers check field types exactly, so a DecibelArray in a power field raises TypeError.
- Hybrid-pol (T2-05): hybrid_stokes_from_covariance(covariance, *, ordering, chi_tx, product_masked, tolerance) returns HybridStokes (j_hh, j_vv, j_hv_real, j_hv_imag, s1..s4 StatedArrays, chi_tx, handedness, transmit_jones, stokes_convention SIS, ordering, tolerance, handedness_verified False, role "context"; covariance_matrix() assembles J). It runs story 3's rules through `_checked_covariance` (returns base, scaled declared-ordering matrices, Hermitian sqrt2 form, exponent), so the shared states match circular_from_covariance. m_chi(s1, s2, s3, s4, *, convention, product_masked, tolerance) and m_chi_from_hybrid(hybrid) return MChi (m, sin_2chi, chi in degrees). lunar_s4_sign_check(s1, s4, valid_mask) returns LunarSignCheck with a SignCheckVerdict. chi_tx -45 = (1, -i)/sqrt2 = SC_LL; +45 = SC_opp.
- Each hybrid output is one linear functional Re sum(R * K) of the (HH, HV, VV) covariance R, with K built from B = [[1, s, 0], [0, 1, s]], s = +-i (`_hybrid_forms`), so every product is exact and cancelling terms vanish in K. Still, np.sum over 9 terms is not correctly rounded (0.5 + 2**52 + 0.5 loses the 1 by ties to even): test sums against exact Fractions to the PRD rtol, not bit equality.
- `math.sqrt(2) * math.sqrt(2)` is 2.0000000000000004. Build (HH, sqrt2 HV, VV) fixtures with an explicit factor matrix whose middle entry is exactly 2.0 (as the module's `_TO_SQRT2_ORDERING`), or exact zero-polarization fixtures pick up 5e-17 residuals.
- Oracles lose precision on subnormal inputs too (math.hypot(5e-324, 5e-324) is 5e-324). Rescale the inputs exactly into the normal range with ldexp, or compute the oracle with decimal at prec 50, which has no float64 range limits.
- The 3x3 identity covariance is not an unpolarized compact-pol return (m = 1/2 for (HH, HV, VV), 1/3 for the sqrt2 form): HV is received in both channels. A reflection-symmetric volume with C = V, A = B, D = E = 0 gives J proportional to I and m = 0.
- G1 (T2-06): `uv run python -m terraluna_pipeline.polarimetry record-g1 --junit <path> --out <path>` reads pytest's junit report against fixtures/polarimetry/g1_required_tests.json (function-level node ids in fixtures F1-F10, conventions and invalid_data per story, real_scene_check) and writes fixtures/polarimetry/g1-record.json. To regenerate it, run the full suite with `--junitxml` outside the repository twice: the first pass rewrites the stale record, and the second is the one to commit.
- T2-07's real-scene test must be pipeline/tests/test_polarimetry_oracle.py::test_real_scene_matches_polsartools, or the list must change (and the record be regenerated). A gate test checks the name once the file exists.

A strict XPASS is a `failure` ("[XPASS(strict)]"), and an xfail is `skipped type="pytest.xfail"`. A collection error is a testcase with classname "" and name set to the dotted module.
