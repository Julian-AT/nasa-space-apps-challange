## Codebase Patterns
- Build Mac, checked 2026-11-14: uv 0.9.26; Python 3.12.13 via uv; Node 22.23.3 (nvm); pnpm 12.16.1; jq 1.8.2; GNU Make 3.81; actionlint installed.
- `python3` on PATH is Anaconda's 3.14. Always use `uv run`, never bare `python3`.
- GNU Make 3.81: no .ONESHELL, no grouped targets (`&:`), no `!=` assignment. Keep recipes POSIX sh.
- No system GDAL (`gdalinfo` is missing). GDAL comes from the rasterio wheel.
- macOS has no coreutils `timeout`.
- Other workers may share this repository. Stage explicit paths only.
- Commits: commitlint (config-conventional, scopes lower case such as t0-01) runs from the husky commit-msg hook (core.hooksPath=.husky/_). The root package.json already exists for this; T0-04 extends it.
- ralph.sh commits review files, gate results, loop notes and compact logs (logs/agents/<date>/*.jsonl). Full transcripts are in git-ignored logs/agents/<date>/raw/.
- ralph.sh matches story `files` with bash `[[ $p == $glob ]]`, so `*` also matches `/`: `pipeline/*` covers nested paths.
- Context7 works over plain HTTP via WebFetch: https://context7.com/api/v1/<org>/<repo>?topic=<words>&tokens=<n>. For flags of an installed CLI, `<cli> --help` is authoritative.
- The uv workspace root is virtual (no [project]). A plain `uv sync --locked` there installs both members and the dev group (checked on a fresh copy).
- Bundle records live in pipeline/src/terraluna_pipeline/schema.py. Base `Record` uses extra=forbid, strict=True, frozen=True and regex_engine="rust-regex". Constraints are kept to what JSON Schema can express (patterns, enums, minLength, minimum), so T0-03/T0-04 can stay in parity.
- Parity traps for T0-03 (both checked with jsonschema 4.26.0): (1) the Python `jsonschema` package matches `pattern` with `re.search`, where `$` also matches before a trailing newline, so "<64 hex>\n" passes `^[0-9a-f]{64}$` there but fails pydantic (rust-regex) and ECMA/zod. (2) pydantic strict rejects JSON `1.0` for an int, while JSON Schema `integer` accepts it and JS cannot tell 1.0 from 1.
- mypy --strict reports a tuple of lambdas that are called later as no-untyped-call. Call the functions directly.
- `mktemp` + `mv` leaves a file with mode 600. Run `chmod 644` after a jq rewrite of prd.json. `jq .` reproduces prd.json's formatting byte for byte.
- Polarimetry results are `StatedArray(value, state, reason)` from terraluna_pipeline.polarimetry: float64 NaN exactly where state != VALID, and reason NONE exactly where VALID. Construction validates and freezes it. Build new rules with the private `_Classifier` (first matching rule wins), and add new codes to `InvalidReason` (value == name, at most 32 chars).
- Name fixture tests `test_F<n>_...` so T2-06 can list the required G1 test ids.
- Masks never enter polarimetry.py implicitly: every array argument goes through `_real_array` or `_bool_mask`, which refuse numpy masked arrays (TypeError). New array arguments must use these helpers, and product flags are explicit arguments (nodata, noise or validity flags).
- polarimetry.py array inputs pass `_require_plain` (an allowlist walked iteratively to every depth): exact np.ndarray or np.memmap, scalars (bool, int, float, complex, str, bytes, np.generic), and lists and tuples up to 64 levels. Anything else raises TypeError (masked arrays at any depth, np.ma.masked, custom sequences, `__array__` objects such as xarray or pandas, third-party ndarray subclasses such as unit-carrying ones), so callers convert explicitly and pass masks as flags. Object-dtype ndarrays pass the walk and are refused by each caller's dtype check; keep that check in any new entry point.
- Update to the bullet above (T2-01 round 3, 0f41cd7): every type in `_require_plain` is matched exactly, never by isinstance. Lists and tuples are `type(x) is list/tuple`, Python scalars are exact bool/int/float/complex/str/bytes plus this module's ObsState and InvalidReason, and numpy scalars count only when `np.dtype(type(x)).type is type(x)`. Subclasses of any of these raise TypeError, since a list subclass with `__array__` hands numpy a masked array the walk never saw. mypy narrows on `type(x) is list`, not on `type(x) in (...)`.
- Results float64 cannot hold are per-element states, never whole-array errors: call `_Classifier.mark_out_of_range(result, positive=...)` after computing a result, which marks INVALID/FLOAT64_OUT_OF_RANGE where the result is non-finite (overflow) or, for a positive quantity, below the smallest normal float64. Compute so intermediates cannot overflow first (decoding uses `(DN * 10**(-offset/20))**2`). This is representability, not a physical threshold.
- Tolerances are `Tolerance(rtol, atol)` from polarimetry.py (finite, not negative, stored as float); `ARITHMETIC_TOLERANCE` is the PRD 7 rtol 1e-10 / atol 1e-12. Use it as the default for later validity tolerances (T2-03 PSD check) and say that the real-data value is open.
- Several outputs from one input share rules through `_Classifier.copy()`: classify the shared input rules once, then copy per output. For a quantity that may be a valid exact zero (SC, CPR), use `mark_below_normal(result, nonzero=<exact test on the inputs>)` instead of `mark_out_of_range(positive=True)`, and decide signs and zeros from the inputs (`s1 <= -s4`, `s1 != s4`), not from the rounded result.
- Stokes results are `CircularPowers(total, sc, oc, cpr, convention, tolerance)` from `circular_from_stokes(s1, s4, *, s2, s3, convention, product_masked, tolerance)`; s2/s3 and product_masked have no default. T2-04's derive_circular should wrap it, not reimplement it.

## 2026-11-14T18:52Z · T2-02 · implement

Returns CircularPowers with total (= S1), sc, oc and cpr StatedArrays plus the convention and tolerance used. New Tolerance dataclass and ARITHMETIC_TOLERANCE; new reasons PRODUCT_MASKED, STOKES_S1_LT_ABS_S4, STOKES_NONPHYSICAL, OC_NONPOSITIVE, SC_NEGATIVE; new _Classifier.copy and mark_below_normal. 108 tests in pipeline/tests/test_polarimetry_stokes.py, F1-F5 named test_F1_* to test_F5_* for T2-06.
- Decisions fixed by the tests: shared rules, first match wins: product_masked -> MISSING/PRODUCT_MASKED; any given Stokes non-finite -> NONFINITE; |S4| - S1 > atol + rtol*|S1| -> STOKES_S1_LT_ABS_S4; with S2 and S3, hypot(S2, S3, S4) - S1 beyond the same bound (on halved inputs) -> STOKES_NONPHYSICAL. s2 and s3 are required keywords (None where the product has none) and must come together. Then per power, a nonzero exact value below the smallest normal float64 -> FLOAT64_OUT_OF_RANGE. CPR then: S1 <= -S4 -> OC_NONPOSITIVE (no epsilon; a tiny positive OC gives its large CPR); S1 < S4 -> SC_NEGATIVE; SC or OC out of range -> FLOAT64_OUT_OF_RANGE. SC or OC negative within the tolerance is reported as computed, not clipped. Without SC_NEGATIVE, S1 = 0 and S4 = 5e-13 (within atol) would publish a VALID CPR of -1. The 2x3 array test puts F2's inputs on the masked pixel, because F1-F5 plus a NaN and a masked pixel is seven pixels.
